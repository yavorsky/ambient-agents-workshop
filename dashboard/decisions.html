Deep dive · fix 2, the gate

A gate that answers in probabilities

An LLM gate writes its verdict as text you parse and hope is right. A decision model reads the event and a set of typed questions, and returns a probability for every answer you allowed, in one forward pass. It can’t invent a label, it’s cheap enough to run on every event, and the probability tells you when to ask a bigger model.

An ambient agent decides all day

Nobody types a prompt. Every webhook, comment and wakeup needs a call: ignore it, act on it, or ask a person first, and which part of the agent should handle it. Most of these calls are easy, and there are a lot of them.

An LLM gate is slow for a reflex

Our step-2 gate asks a model for JSON. It works, but each call takes seconds and hundreds of tokens of prompt, so you batch events and wait. The race below measures it.

A decision model is the reflex

It answers the same questions in one forward pass, returns a probability for each option, and never writes text. Confident answers settle the event; unsure ones go to the LLM.

01 · how it works

State in, typed questions in, probabilities out

You describe the situation (the state) and ask questions with a fixed set of answers. The model scores every allowed answer at once; no text is generated, so the output is always one of your options.

choice

Pick one of named options, each with a description. Returns the choice, a confidence and a probability per option. Our action: act, ignore or ask.

noul

A yes/no question. Returns the probability that it is true. Our routing: one per signal, so an event can match CI and issues at once.

score

Ordered levels (none, low, high…). Returns the expected level and the distribution. Useful for urgency or severity.

02 · when to use which

LLM gate or decision model

They are not competitors. The decision model is the fast reflex (“System One”); the LLM is for the cases that need thought.

LLM gate (structured output)Decision model (Jev, Clef)
OutputGenerated JSON with a verdict and a reasonA probability for every allowed option
Invented labelsPossible; schemas and retries keep it in checkNot possible: only your options are scored
Knowing it’s unsureSays everything with the same confidenceThe probability is the signal: below a threshold, escalate
SpeedSeconds per call, so you batch eventsClef-Flash 38.8 ms, Clef 209 ms median model time (Cloudflare’s numbers). From a laptop, with the network, we measured about 0.4–0.5 s per call for Clef; one call per event
PriceInput and output tokensClef: $0.24, Clef-Flash: $0.038 per million input tokens, output not charged; 10,000 free Neurons a day (about 900 Clef gate calls)
LimitsContext window of the modelClef: 1–64 questions per call, 65,536-token context, up to 4 images
Use it forReasoning, writing, tools, the hard 10%Filtering, routing, triage, guards, at volume

03 · our gate

The cascade: code, then a decision model, then an LLM

Each tier only sees what the cheaper one before it couldn’t settle. GATE_MODE=decision runs this in the workshop app.

// src/gate.ts · decision mode (excerpt)
const results = await Promise.all(batch.map((e) => decide(options.provider, eventState(e), GATE_QUESTIONS)));
batch.forEach((event, i) => {
  const action = results[i]?.answers.action;
  if (action?.type !== 'choice' || action.confidence < options.threshold) return unsure.push(event);
  // confident: settle it, and route to the signal with the highest "yes"
  verdicts.push({ id: event.id, action: action.choice, signal: topSignal(results[i]), confidence: action.confidence, reason: … });
});
// below the threshold: a second opinion from the LLM gate
if (unsure.length) verdicts.push(...await modelVerdicts(unsure, model));
04 · playground

Ask the same question every way

Pick an event, edit the state or the questions, and run them through each provider. The verdict line shows what the gate would do at the current threshold.

Writing questions that work
  • Describe every option. The criteria text is what the model scores against: “real work the agent should do (new issue, red CI, real question)” beats a bare “act”.
  • Keep choice options exclusive. If two can be true at once, use one yes/no (noul) per option instead. That is why routing is three nouls, not one choice.
  • Put only what decides it in the state. Kind, author, title and body. Leave out ids and timestamps unless the answer depends on them.
  • Ask several things in one call. Up to 64 questions share one forward pass, so the action and the route cost one call, not two.
  • Set the threshold from your own events. Run the storm below, then move the slider until the settled answers are right; everything under it goes to the LLM.
  • Try breaking it. Edit the body of an example (“+1” → “+1, also crashes on logout”) and watch the probabilities move.
